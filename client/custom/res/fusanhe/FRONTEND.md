# 福三和 CRM 第一阶段前端

2026-09-18；EspoCRM 10.0.8；分支 `codex/fusanhe-crm-frontend`。

## 实现

- 官网原始 Logo、108 KB 工厂 WebP 和本地品牌变量；登录保留 EspoCRM 版权。
- 原生可折叠导航，森林绿底，单色图标，中文业务名称；系统管理仍在账户菜单。
- 首页十项紧凑指标与六个业务区域。使用受 ACL 约束的实体 GET 分页查询，不调用原有会更新 SLA 记录的 `Fusanhe/dashboard`。
- 统一询盘列表：文本搜索、渠道、负责人、国家、状态、未读、120 分钟 SLA 筛选、最后消息排序、清除、分页；整行点击或 Enter 打开会话，客户名称直接打开客户；长文本省略与提示。
- 会话详情：最近会话、消息时间线、客户资料和审核三栏；原文、译文、附件名称、送达状态、失败任务、引用资料链接。保留原生详情及关系区域。
- 草稿保存、拒绝、生成与批准入口。批准要求再次确认并勾选人工审核。已审批或已发送草稿在会话审核区不可重复修改/批准；没有批量批准。
- 客户公司、联系人、线索：原生详情布局精简，增加只读业务概览及最近询盘、待办、平台身份；缺失信息如 WhatsApp 明确显示未记录。
- 草稿队列、知识文档、发送任务和执行端采用同一紧凑列表。执行端超过 5 分钟无心跳时显示“心跳超时”。
- 原生 JSON 字段缺失视图已通过自定义结构化只读展示修复，避免 JSON 原文或缺失脚本。
- 中文及英文 UI 字典，原生枚举中英文翻译；英语询盘列表已实际切换验证，最终恢复简体中文默认。

## 官方扩展点

- `metadata/app/client.json`：附加本地 stylesheet。
- `metadata/clientDefs/App.json`：`loginView`。
- `metadata/clientDefs/Home.json`：自定义 Home controller。
- `clientDefs/<Entity>`：原生 record controller、list view 和 record detail view。
- `entityDefs.fields.*.view`：结构化字段渲染；未新增数据库字段或改变业务逻辑。
- 自定义布局、i18n、Espo 主题 Logo；未修改 core、vendor、镜像原始文件或业务 PHP。

## 部署和复现

在项目根目录运行：

```sh
docker compose exec -T espocrm bin/command rebuild
python3 client/custom/res/fusanhe/configure.py
```

`configure.py` 只设置中文默认与导航顺序，读取本地已忽略的 `.env`，不打印凭证；运行前同时检查 `.env` 与当前容器均为全局停发。设置通过原生 Settings API 保存，脚本可版本追踪。首次实施时发现 `.env=true` 而旧容器仍为 false，已执行 `docker compose up -d --force-recreate espocrm`，验证 PHP 进程的有效值为 true。

升级后完整刷新浏览器。开发过程中只切换路由不能卸载已加载的 AMD 模块，新旧脚本混用会产生暂时的 `localize is not a function`；完整刷新后已验证解决。

## 设计与响应式

品牌色来源和资源地址见同目录 README。控件 32–34px、表格约 40px、6px 圆角、12/13/14/16/20px 字级。白色内容、细边框、弹层之外不加阴影。表格保留横向滚动，不转换成卡片。

- ≥1280px：三栏；可折叠原生导航。
- 900–1279px：会话列表和时间线两栏，右侧资料/审核放到下方全宽区，保证原生兼容性。
- <900px：会话、消息、资料审核分区切换；登录隐藏工厂图。
- 登录和核心页面已检查 1920×1080、1440×900、1280×720、760×900；会话另外检查 1024×768。

## 明确限制

1. 现有 API 没有无副作用的发送开关读取接口。因此本阶段停发提示对应已验证的固定部署状态，不是实时开关监控。之后若允许切换发送状态，必须先补只读状态接口并让 UI 从接口读取，不能只改环境变量。
2. 当前真实数据仅有既有演示线索、会话和已发送草稿；Account/Contact 无记录，已验证空状态与布局定义，不能声称用真实记录跑通全部客户类型。
3. 为遵守不修改业务数据，未对现有记录执行保存/批准；未接入任何真实平台。现有历史演示任务的“已发送”是历史状态，本轮没有发送。
4. 首页按权限范围读取全量实体计算，适合当前阶段；大量记录时应增加后端只读聚合接口。人工修改率依据现有 `wasEdited` 或 `edited` 状态，历史数据完整性取决于原有流程。
5. 会话左栏取最近 50 条，消息取最早 200 条，并提供原生历史入口；不宣称无限加载。附件仅呈现已记录名称，不伪造没有下载地址的附件链接。
6. 当前客户模型没有独立 WhatsApp/阿里/MIC 联系字段，平台身份从关联询盘读取，缺失项明确提示；商机、活动、邮件、任务仍使用原生关联区域。
7. 结构化数组/对象在原生表单中只读，避免技术 JSON 暴露。完整草稿审核请使用会话审核区；原生后台编辑权限未被擅自收紧。
8. 部分动态提示/混合业务内容仍使用中文，英语主要导航、筛选、表头和状态可用；不翻译客户消息和资料正文。

下一阶段建议：只读运营聚合与停发状态 API、标准食品行业客户字段、附件下载与历史分页、大数据量/多角色验收；继续保持外发暂停，另行安排真实平台接入。
