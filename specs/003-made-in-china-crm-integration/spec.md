# Made-in-China 完整会话与 CRM 接入

状态：计划中（2026-09-23）。本文件描述目标，不表示已经交付。

## 已确认的用户决策

- 将 MIC 询盘正文及其后买卖双方逐条聊天历史导入 CRM，并持续增量同步。
- 有稳定 MIC 买家标识时先建立 Lead；缺少的资料留空，后续补全。
- 问候由 CRM 草稿经人工批准后生成任务，再由 MIC 执行端发送并回写结果。
- 先完成计划，后续实现任务交给 GPT-6 Luna（high）。

## 范围

**MIC-01 历史回填：** 网关遍历全部可访问询盘及其 TradeMessenger 历史，保留询盘正文、双向聊天、源顺序、时间、发送方、附件元数据。页面或接口不完整时报告失败，不将局部结果标成完整。

**MIC-02 增量同步：** 新询盘、消息和买家资料按稳定源标识更新；重跑、分页中断和网络重试不产生重复会话、消息或 Lead。若聊天源没有持久消息 ID，必须通过现场证据证明降级指纹在实际变更下仍满足去重，或保持导入验收未通过，不能以合成夹具代替证明。

**MIC-03 潜在客户：** CRM 按平台账号与稳定买家标识解析身份。无可靠既有客户匹配时创建一个 Lead，并将同一买家的会话关联到它；姓名未知时使用明确的临时显示名，真实资料到达后补全。不得仅凭姓名合并不同买家。

**MIC-04 审批发送：** MIC Agent 只能领取 MIC 渠道、已批准且允许执行的任务；全局停发、人工接管、任务状态和登录失效均阻止发送。网关 Outbox 的 `queued`/`sending`/`uncertain` 不算 CRM 成功；只有平台确认后才回写成功。

**MIC-05 可观察性：** 能查看网关登录、源同步进度、CRM 导入进度、Agent 心跳、Outbox 状态、失败及人工介入原因，不在日志或规格中保存真实买家资料和凭据。

## 验收场景

1. 脱敏夹具含一条询盘、后续买家消息、后续卖家消息；CRM 显示三条且顺序正确，再次导入数量不变。
2. 同一稳定买家 ID 的两个询盘关联同一 Lead；不同 ID 即使同名也不能误合并。
3. 历史回填不触发 AI 草稿、未读副作用或外发任务。
4. Agent 不能领取其他渠道任务；停发开启时 MIC 网关没有新的发送请求。
5. 人工批准一条问候后，网关确认发出才把 CRM 任务置为成功；超时或结果不明进入待对账状态，禁止盲重发。
6. 聊天组件不可用、登录过期或源契约变化时保留断点并给出明确错误，不声称完成。

## 边界

本特性不导入 MIC 订单到 CRM，不创建自动群发或免审批规则，不修改 Alibaba 现有发送流程。真实账户的只读验收与真实发信验收分别记录；真实发信只使用经人工批准的指定测试会话。
