# 每晚 22:00 持续获客

用户确认的流程：北京时间每天 22:00 搜索新客户 → AI 筛选 → 去重入库 → 现有五级评级和价值分流。次日 09:00 的全公司统一微信晨报显示实际新增数量和运行异常。

## 服务器调度

在 22005 服务器 `/home/fusanhe/services/outreach` 运行。用户 systemd timer `fusanhe-acquisition.timer` 使用 `OnCalendar=*-*-* 22:00:00 Asia/Shanghai`，由 `fusanhe-acquisition.service` 调用 `nightly-acquisition.py`。用户已有 Linger=yes，退出 SSH 或关闭 Mac 不影响运行。首次正式执行为 2026-10-13 22:00；对应晨报为 2026-10-14 09:00。

每个北京时间计划日期仅领取一次。与原有手动试跑共享 flock；终态重放只同步记录，不重新调用付费数据源或模型。服务最长运行 40 分钟，各阶段另有超时。Persistent=true 支持服务器恢复后补执行，补执行限原计划的两小时内；超过窗口记录 missed。中断后停止对应容器、保留已经完成的入库并写入失败记录，不自动重跑整批。

## 搜索和筛选

- Xpoz 按日期轮换 28 个食品行业关键词中的 3 个，每个查询选取最多 6 个新的公开账号候选；全部新候选可以补查，不再使用旧试跑的固定账号名单。
- 对已入库 sourceId 跳过；已成功筛选的其他账号保留 30 天历史，之后可复查。搜索、补查和筛选输出每晚独立保存；阶段中断保留已经获取的资料。
- 大模型使用现有 GPT-6.1 Sol Responses 网关，按福三和面包糠、裹粉、泡打粉、玉米淀粉筛选进口/分销企业和食品/烘焙加工企业。英美市场优先，其他初步匹配必须保留地区、采购意向和需求的不确定性。
- 来源简介为不可信数据，模型忽略其中的指令。每个候选必须有独立判断；入库前检查来源 URL、稳定 sourceId 和实际资料字段中的原文引用，不生成联系方式或采购需求。
- OpenOutreach 使用 `find 2 --new --json --exclude ...`，延续已有发现历史，排除 CRM 中已有 LinkedIn 来源。流式保存完成记录，超时也能保留已发现的合格联系人。
- 上述数量为有限查询批次，沿用用户取消每日 15 次目标的决定，不设置“每天必须获得多少客户”的业务配额。未调用购买地址参数，未调用 OpenOutreach 邮件发送命令。

## 入库、评级和分流

使用原有 Muse prospect API 与专用获客凭据。入库前按稳定来源 ID、规范化公开来源 URL 和精确邮箱与 Lead/Account/Contact 做匹配；同一批次也按这些标识去重。已转换为 Account/Contact 的来源保持原客户关联。模糊同名不自动合并。

native API 返回真实 prospectId 后才计入确认新增；超时或丢失回执记录 uncertain，后续按稳定来源与 CRM 快照核对。已创建的 source identity 和 CRM API 本身仍提供事务去重。

入库创建触发现有每分钟客户评级任务。新客户先为 pending_rating，完成评级后自动持久化分流：S/A → human；B/C/D → ai；未评级 → pending_rating；拒绝联系 → blocked。人工评级优先，人工接管仍被保留。晨报读取当前实际评级与分流，而不是把入库时的待评级快照当成最终结果。现有邮件任务继续按既有设置执行。

## 晨报与运行记录

主机每次执行的数据存于 `state/nightly-acquisition/YYYY-MM-DD/`，包含私有 run.json、日志、候选、判断和入库确认。桥接命令仅限 CLI，写入共享 CRM volume 的 `data/fusanhe/acquisition-runs/YYYY-MM-DD.json`；目录 0700、文件 0600、owner/group 与 CRM data 保持一致。设置 firstDate=2026-10-13、timezone=Asia/Shanghai、runTime=22:00。

MorningReportService 读取前一天的计划日期。晨报的原有 AI 昨日新增/累计仍使用 Lead 首次 createdAt，另显示昨晚执行状态、取得的候选、筛选通过数、确认新增与重复跳过数。搜索/模型失败、来源证据校验失败、入库失败/不确定、中断、缺少执行记录、错过窗口均进入“运行提醒”。成功的空搜索是有效零；日志不可读取不会伪装成零。

验收执行使用单独 acceptance 记录，保留真实新客户，不占用今晚正式领取，也不写假定时记录。2026-10-13 已发送晨报与投递 ledger 保持原样。
