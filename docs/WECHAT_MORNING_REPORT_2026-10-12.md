# 微信统一晨报

按用户确认，所有已绑定且开启 CRM 提醒的账号，每天北京时间 09:00 收到同一份福三和晨报。初次启用在 09:00 之后时，从次日开始，避免下午补发。2026-10-12 上线，首个计划日期为 2026-10-13。

## 内容和口径

- 昨晚：前一天 19:00 至当天 09:00，北京时间，右边界不包含。
- 自动回复：OutboundTask.triggerType=scheduledReception、executionMode=real、status=sent，且 completedAt 在夜间窗口。按客户关联去重人数；消息数按任务 ID 去重。排除模拟、手工、未发送及未确认任务。
- 待人工接手：上述已回复客户中，未关闭、S/A 或人工控制的客户；在 09:00 生成交接 Task 之前也能统计，避免调度先后造成漏数。
- 昨天新增：CRM 前一天 00:00 至 24:00 创建的 Lead，按 ID 去重，包括销售手工录入与渠道线索；不是整个平台历史客资总数。
- S/A：遵循既有人工评级优先、已完成 AI 评级兜底的规则。
- 联系方式：新建 Lead 含格式有效且非重复单一数字的电话或有效邮箱，每条线索最多一份。不表示联系方式已核验可达，也不把旧客户资料补全计入新增。微信文案为“新线索中留有有效联系方式 X 份”，避免把导入线索误称为客户主动留资。
- 重点：最近收到的真实询盘包含报价、交期、样品、认证、规格等固定信号，以及高价值、未分配新线索。每项保留来源消息 ID、负责人及 CRM 链接，客户去重，最多三项。第一版采用证据规则生成措辞，不依赖额外模型推断或上传原始对话。
- 运行提醒：发送失败、结果待确认、自动接待停用、渠道连接异常或同步超过 30 分钟未更新。数据库读取失败时中止生成，不填零。

## 运行与状态

EspoCRM ScheduledJob `FusanheMorningReport` 注册为 Active。调度器调用 MorningReportService::tick，内部以 Asia/Shanghai 判断时间，只在 09:00–09:15 接受当天任务；不是桌面线程的定时提醒。

数据快照截止当天 09:00。先保存一份固定文本和哈希，再依次发送，发送期间不重新生成。每天每个接收账号有持久 claim；成功、失败或不确定结果不会自动重发。进程异常退出后的 preparing 记录转为 uncertain。首次无接收账号时仍保存晨报，发送记录明确为空。

微信客户端 ID 按账号与日期生成。发送前再次检查绑定凭据和提醒开关。明确数字 ret=0，或 ret 省略但返回有效 uint64 message_id 时，计为 sent；显式非零 ret/errcode 优先判为失败。超时、非法/缺失回执、丢失响应计为 uncertain。微信拒绝或无法取得会话计为失败，在页面显示对应原因。无会话上下文时不发送；接收人需要先在微信 ClawBot 中向该连接发一条消息。

跨夜主动推送是否稳定仍须真实过夜验证；绑定成功不是送达成功。上次测试结果不确定时不宣称已送达。

## 页面与访问

“微信接入”增加统一晨报开关、真实数据预览、历史日期、完整内容、来源记录链接及各账号发送状态。预览不保存、不发送。晨报链接 `?workspace=wechat&reportDate=YYYY-MM-DD#Home/workspace`。

- GET /Fusanhe/wechat/morning-report：管理员管理总览。
- GET 同路径，date=YYYY-MM-DD：登录且具有 Lead 和 ExternalConversation 读取范围的 CRM 用户可查看用户明确授权的全公司统一晨报；非管理员不返回收件账号/投递日志。来源记录打开仍遵循 CRM 原有记录权限。
- POST 同路径：仅管理员 configure 或 preview；没有匿名发送或任意文本推送接口。
- 记录存于 data/fusanhe/morning-reports/YYYY-MM-DD.json；设置和记录 0600，目录 0700，保持 CRM data 的 owner/group，兼容 web 和 daemon。微信凭据仍只存在原来的私有账号文件。
